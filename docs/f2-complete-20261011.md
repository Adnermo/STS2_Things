# F2 自动诊断补全 — 1.25.18

2026-10-11。补齐二层卡住报告暴露的信息缺口。玩家仍在原版 F2 中选择“琐事 Bug（上传本局）”，随便描述问题即可；不增加额外必填项。普通反馈类别继续使用原版发送流程。

## 新增内容

- **异常覆盖**：原版 `Log.LogCallback`、Godot `Logger` 和未处理的托管异常。捕获异常类型、嵌套类型、方法栈、缺失 API 签名和时间；支持 Godot 编号栈帧及初始化前的日志回填。最近 32 条独立持久化，重启保留并标注“上次运行”。不吞异常或改变任务结算。
- **环境可识别**：游戏和模组版本、程序集 MVID、模组名称／来源／原生工坊 ID／实际加载顺序、DLL/PCK 的大小及 SHA256。哈希在后台线程计算，文件变化时失效刷新。琐事本地和房主生效配置自动附上。
- **多人及界面现场**：房主／客户端／单人类型、本地玩家序号、连接／加载状态、每名玩家动作队列及暂停／取消状态、当前动作、手牌实例／费用／全部牌堆、原生卡牌和遗物保存属性、充能球、敌人意图、结束回合按钮、场景暂停及时间缩放。开战等待超过 15 秒时记录观测，不能据此直接判定 bug。
- **原版截图**：使用原版 F2 打开前截取的画面，压成不超过 60KB 的 JPEG；后台仅管理员可查看。玩家输入框注明附带游戏画面。
- **战前还原**：在 `CombatRoom.EnterInternal` 执行前调用原版 `RunManager.ToSave` 与原版 JSON codec，保留 RNG 完整状态、地图／章节／事件池、角色、遗物和卡牌内部属性。匿名玩家改为 1…N，压缩并核对 SHA256；后台下载原生 `.save`。
- **可靠上传与后台**：schema 3，兼容旧 schema 1/2；失败报告的 ID 和正文冻结、独立入队并显示回执。完整证据先落盘，上传缩减保留检查点，省略内容明确标注。新快照避免 JavaScript 大整数舍入，JSON 导出返回服务器原始正文；空药水槽正常显示。

## 还原入口

从后台导出报告 JSON 后，准备匹配游戏版本、匹配模组的已停止 Workbench 私有实例：

```powershell
python scripts/restore-f2-checkpoint.py report.json --output checkpoint.save --instance <instance_id>
```

脚本验证格式、大小、SHA256 和匿名 ID；只写入指定私有实例并保留原存档，不接触玩家 Steam 主存档。启动该实例后通过原版“继续游戏”读入。可只指定 `--output` 导出文件，不安装到实例。

## 边界与数据

原版存档用于重新执行战斗入场，不能恢复卡住的线程、已收到的网络包或真实联机消息时序。事件内战斗沿用事件存档入口，不承诺像普通遭遇一样直接读入。第三方配置没有统一导出协议，本轮不收集任意配置文件。未知第三方模型仍需相同模组代码与设置。

已知身份、凭据字段和绝对路径从原生保存数据／结构化快照中去除；原生 RNG 数值不重映射。异常不上传原始日志正文、路径、凭据或局部变量。截图保留原版画面里实际可见的内容。文件指纹会报告是否尚在计算或不可用。

托管异常会尽力在退出前保留；操作系统强杀、原生硬崩或存储失败无法保证保存最后一条报错。旧报告没有存档或未记录的异常不能事后补回。此前二层无手牌报告仍未确认根因，本轮没有宣称修复该卡住问题。
