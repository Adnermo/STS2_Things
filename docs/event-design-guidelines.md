# 自制事件设计规范

用户最新约定（2026-11-24 全面去「老好人」化更新）：**所有普通策略事件的福利都必须有明确、贴合主题的真实代价**，不再为“无损兜底选项”白送免费回复、最大生命、随机升级、药水或金币；安全退路统一为**纯粹「离开」（无收益）**（5 款联机小游戏独立维持各自玩法设计）。

- 普通策略事件的每一项正面收益（删牌、变化、升级、附魔、遗物、药水、回血、金币等）均应匹配真实代价（生命、最大生命、金币、诅咒、牌/遗物交换或战斗），避免出现零代价白嫖或远低于尖塔经济基线的“老好人”福利选项。
- 涉及伤害或降低最大生命的选项必须挂接 `.ThatDoesDamage(...)` / `.ThatDecreasesMaxHp(...)`，且扣血后先检查 `Creature.IsDead` 再发放奖励，绝不向阵亡玩家结算收益。
- 不愿承担代价或资源不足时，保留纯粹「离开」作为合法退路，确保不会因缺血、缺钱或满药水栏而软锁。
- 分支结算后的「继续」「结束」用于结束已经结算的流程，不再重复奖励。取消选牌应返回选择页面，不以空结局替代收益选项。
- 选项独立清楚，玩家直接看见代价与所得；风险和战斗在选择前写明。洞胃四种喂食直接展开，再提供小收益选择。
- 原版事件文风：第二人称、具体动作、短对白与简短反应；效果说明直接写「移除……。获得……。」。参考当前原版事件表，不用模糊隐喻替代动作和效果。
- 多人先确定选择是否共享。个人交易只改变各自资源；切换战斗使用原版共享事件同步；休息点各自结算，用原版选项协议完成房间。
- 用原生存档属性保存跨房间收益与代价，保留领取标记，处理重复载入、死亡延迟和跨章节情况。
- 每次调整后审查所有可选路径：有合法选择、没有重复领取、没有仅因为缺少资源而卡住；查看中英文与多人排版。验证方式遵守当前用户授权。

## 事件遭遇门槛（`IsAllowed`）标准（2026-11-26 多人放宽修订）

所有自制事件在进入房间前必须按以下门槛标准重写 `IsAllowed(IRunState runState)`，在兼顾联机局事件丰富度的同时，避免出现“全队主选项全锁、满血进纯病房、开局过早撞牌组折磨、残血队友进房无安全退路或共享投票状态失步”等问题：

1. **单人保底、多人任一存活玩家达标即可进房（`Players.Any` + 内置存活校验）**：
   - 2026-11-26 起废止旧版“全员必须同时达标（`Players.All`）”的严苛门槛，所有事件统一改用 `runState.Players.Any(player => !player.Creature.IsDead && ...)`（多人专属事件前置 `runState.Players.Count > 1 && ...`）。
   - 单人局中 `Players.Any` 自动等价于唯一存活玩家达标；多人局中只要至少 1 名存活队友满足条件即可触发事件，不再因个别队友已阵亡、残血、缺钱或牌组偏科而封死整队事件池（原版 `EventModel.BeginEvent` 会自动完结已阵亡玩家的事件实例）。
   - `!player.Creature.IsDead` 必须写在 `Any(...)` 谓词内部，严禁以阵亡玩家的状态作为放行依据。
2. **按「最低可用主分支」卡门槛，而非按最高档锁房**：
   - 存在多档费用或多条并列主线的事件，只要求至少 1 名存活玩家满足**最低可用核心分支**即可（如低档金币下限、任一可交易遗物／药水、或任一合法附魔／删牌／变化／合并目标），不再按最高档位或全员同时达标锁房。
   - 发放唯一专属事件遗物或跨房契约（如《发烫的蜡封匣》《影子寄存处》《菌根借贷所》《温热的育王巢房》）的事件，仍须检查该存活玩家尚未持有对应遗物且距当前章节 Boss 尚有足够房间。
   - **纯回血事件**（所有选项均为回血，如《满员的病房》）维持反向血量上限（`CurrentHp <= MaxHp * 0.75m`），避免满血白逛。
   - **前期高折磨事件**（如《借牌老藤》）仍须卡最低层数（`TotalFloor`）与最低血量，避开开局前几格只有基础牌的极端局面。
3. **低血量／未达标队友的兜底安全退路（0 伤害 `LEAVE`）**：
   - 放宽为 `Players.Any(...)` 后，允许残血或缺少资源的队友随队进入事件房；凡核心选项均需扣血／扣最大生命且原无无损退路的事件（如《墙缝账房》无遗物可典当且 `CurrentHp <= 8`、《跌倒／后室》极端 `CurrentHp <= 2 && MaxHp <= 5`），必须在对应低血边界下提供纯粹、0 伤害的兜底「离开」（`LEAVE`）选项，避免残血队友被迫自杀或软锁。
   - 多人共享投票事件若含全员扣血选项（如《谁去推门》全员 `-12`），`IsAllowed` 仅需至少 1 名存活玩家满足安全血量（`CurrentHp > 12`），同时保留 0 伤害安全分支（如「钻狭缝绕路」）与 `.ThatDoesDamage(...)` 致死警示。
4. **多人共享事件（`IsShared => true`）选项锁态必须全端一致**：
   - 共享投票事件在 `GenerateInitialOptions()` 中生成的选项列表与每项锁定／解锁状态必须对全队完全一致，**严禁**依赖单个 `EventOwner` 的局部血量、牌库或 `_offeredRelic != null` 决定按钮锁态，防止联机投票与房间同步出错。
   - 以《礼貌的洞胃》（`ThingsPoliteMaw`）为例：攻击／技能／能力／诅咒四个喂食选项统一按存活玩家 `Any` 判定解锁；仅对自身满足条件的 `EventOwner` 挂载 `.ThatDoesDamage(...)`／`.ThatDecreasesMaxHp(...)` 警示并在 `BeforeEventStarted` 中按需预抽遗物；投票执行后，不满足该分支条件的队友走 `NO_FOOD` 无伤无奖完结，满足条件的队友各自完成删牌、代价结算与领奖。

此约定适用于自制事件，当前同步到深处事件。原版事件池中的原作事件保持其原有选择。
