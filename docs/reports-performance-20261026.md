# 玩家报告与性能修复 — 1.25.24

2026-10-26。后台共 56 条报告，本轮读取前次审查后的 7 条新报告，后台状态保持不变。本轮使用独立原生测试进程；未改玩家存档，也未进行真实 Steam 多机联机或整局帧率测试。

## 性能

固定夹具使用真实 STS2 卡牌、记录器回调与原生 Hook：68 张战斗牌（8 张手牌）、700 条历史，模拟 100 次行动的开始／完成回调。海克斯对照使用本机保留的 HextechRunes 0.9.7、真实 `HextechMayhemModifier` 与全局费用分派；正常费用查询先确认确实进入该修饰器。

| 检查 | 旧版 1.25.23 | 修复后 |
| --- | --- | --- |
| 200 个行动回调总耗时，无海克斯 | 2811.970 ms | 1.681 ms |
| 单次行动前后回调中位数，无海克斯 | 27.602 ms | 0.009 ms |
| 主线程分配，无海克斯 | 535,471,416 bytes | 560,864 bytes |
| 额外 CanPlay 调用 | 1600 | 0 |
| 200 个行动回调总耗时，真实海克斯修饰器 | 3094.555 ms | 1.397 ms |
| 主线程分配，真实海克斯修饰器 | 860,886,416 bytes | 560,864 bytes |
| 额外海克斯费用调用 | 15200 | 0 |

这些数字测的是记录器的额外开销，不是游戏 FPS，也不是对玩家全部掉帧现象的完整复现。

根因是每个行动事件都重新遍历整局牌组／历史，查询 `CanPlay()` 和全局费用 Hook，再在游戏线程序列化、读取旧文件、备份并写整份记录。重复异常还会逐条重复上述流程。

修复后，行动事件只追加轻量记录；自动快照最多每 500 ms 合并一次，空闲且没有新事件时不重复抓取。后台只处理冻结的结构化 JSON 和文件 I/O，不接触游戏／Godot 对象。主动 F2 上报立即采集并等待最新记录落盘。保留检查点、截图、异常、行动队列、重试和备份恢复；自动保存最多落后约半秒。

诊断不再调用 `CanPlay()` 或全局费用修饰；保留本地临时费用并标注 `energy_scope=local`，实际手牌显示费用仍从 UI 读取。定时与主动快照均验证为零次全局费用／海克斯费用调用。相同异常合并计数，保留首次／末次时间和不同故障；后续报告增加原生 FPS、process/physics 时间读数，方便定位尚未复现的掉帧。

## 有确定性复现的玩法修复

- `fcc0e798`：怪癖草蜢优先挑选诅咒，却没有排除永恒牌。现在使用原版 `IsRemovable`，同时检查战斗牌和对应永久牌；只有永恒牌时没有可偷取候选，普通诅咒优先级和返还流程保留。v107.1/v111 旧包红、新包绿。
- `7f13ef2b`：活体巨岩本体是部分招式的真实攻击者，但埋藏核心的零伤害规则也抵消了原生荆棘。现在只在本体原生攻击命令执行期间允许玩家的无来源卡、非强化反伤命中本体。荆棘使用原版伤害流程；埋藏核心仍不可选，普通直接伤害继续无效，暴露期规则保留。两版本覆盖 1／2／4 人模型，旧包红、新包绿。
